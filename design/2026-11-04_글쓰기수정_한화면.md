## 2. 화면 흐름

```
[글쓰기] GET /board/write        ─┐
[수정]   GET /board/edit/{번호}  ─┴→ 같은 화면(board/form.html), 글이 있으면 수정 모드
   └ 버튼 → JS fetch(form.action)
       ├ 성공 → alert → 상세(/board/detail/{번호})
       ├ 빈 제목(400)·지정 밖 파일(400) → 서버 문구 alert, 그 자리, 입력 유지
       ├ 남의 글(403)·없는 글(404, 수정만) → 서버 문구 alert, 그 자리
       ├ 화면 만료(CSRF 403, 본문에 문구 없음) → "화면이 만료되었습니다…" alert
       └ 413 / 전송 실패 → 지금 그대로
```

## 3. 한 화면에서 갈리는 것 — 기준은 `board`가 Model에 있나

| 자리 | 글쓰기(`board` 없음) | 수정(`board` 있음) |
|---|---|---|
| 제목(h1)·`<title>` | 글쓰기 | 글 수정 |
| 처음 값 | 빈칸 | `th:value="${board?.title}"`, `th:text="${board?.content}"` (`?.` = 없으면 null → 빈칸) |
| 보낼 곳(`th:action`) | `@{/api/board/save}` | `@{/api/board/update/{idx}(idx=${board.boardIdx})}` |
| 파일 칸 | 보임 | **안 보임**(`th:if="${board == null}"`, 수정은 파일을 안 다룸) |
| 버튼 글자 | 게시글 작성 | 수정 |
| 취소 | (없음) | 상세로 |
| 성공 alert | 저장되었습니다. | 수정되었습니다. (8장) |

- `th:action`이 POST 폼이면 어느 쪽이든 CSRF 숨은 칸이 들어가고, JS는 `form.action`만 쓰므로 **JS는 주소를 몰라도 됨**.
- 화면 GET 컨트롤러 둘(`boardWrite`, `boardEdit`)은 그대로 두고 반환 화면 이름만 `board/form`으로. 수정 화면 GET의 실패 갈래(없음·남의 글)도 그대로.

## 4. 수정 API(새로)

| 항목 | 내용 |
|---|---|
| 주소 | `POST /api/board/update/{boardIdx}` (저장 `/api/board/save`와 같은 규칙) |
| 받는 것 | `@PathVariable boardIdx`, `@ModelAttribute BoardWriteRequest`(FormData → multipart, 저장과 같은 방식), `@AuthenticationPrincipal LoginMember` |
| 성공 | **200** `ResponseDto<Integer>`(`data` = 글 번호 — 저장과 같은 모양이라 JS 성공 갈래를 하나로) |
| 실패 | try/catch 없음 → `ApiExceptionHandler`: 빈 제목 400, 남의 글 403, 없는 글 404(모두 `ErrorCode` 문구) |

## 5. JS(한 벌)

- 성공: `await res.json()` → alert → `location.href = '/board/detail/' + body.data` (저장·수정 공통)
- 403: 지금 고정 문구 → **`body.message ?? '화면이 만료되었습니다. 새로고침 후 다시 시도해주세요.'`** — 같은 403이라도 남의 글(우리 `ErrorCode`, 문구 있음)과 CSRF 거부(부트 기본 JSON, `message` 없음)를 문구 유무로 가름(TODO 11/02 "403 종류별 문구")
- 크기 미리 검사: 파일 칸이 없는 수정 모드에선 `form.file`이 없음 → `form.file?.files[0]` 꼴로(칸이 없으면 검사 건너뜀)

## 6. 지우는 것

- `templates/board/write.html`·`edit.html` → `board/form.html` 하나로(파일 이름은 8장)
- `BoardController.updateBoard`(`POST /board/update/{boardIdx}`, form 길) — fetch로 옮기면 안 쓰는 길(11/04 저장 길과 같은 판단)
- 수정 화면의 `errorMessage` 안내 줄 — 채우던 곳(form 수정 실패 redirect)이 없어짐. 단 **상세·목록의 안내 줄은 그대로**(수정 화면 GET 실패가 거기로 감)

## 7. 확인 방법

| 해 볼 것 | 성공 기준 |
|---|---|
| 글쓰기(파일 없이·있이) | 지금처럼 저장 → 상세 |
| 내 글 수정 | 처음 값이 채워져 있음, 파일 칸 없음, 수정 → "수정되었습니다." → 상세에 바뀐 내용 |
| 수정에서 제목 비우기 | 서버 문구 alert, 그 자리, 입력 유지 |
| 남의 글 수정 화면 주소 직접 | 지금처럼 상세 + 안내(화면 GET) |
| 수정 화면을 띄워 둔 채 다른 탭에서 로그아웃 → 수정 | "화면이 만료되었습니다…" |
| 수정 화면을 띄워 둔 채 다른 탭에서 그 글 삭제 → 수정 | "게시글을 찾을 수 없습니다." (404) |
| Network | 수정 요청 주소 `/api/board/update/{번호}`, 200, `data`에 번호 |
