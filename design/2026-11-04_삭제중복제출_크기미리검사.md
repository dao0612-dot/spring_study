## 2. 삭제 버튼 중복 제출

**지금**: 삭제는 form 제출. 빨리 두 번 누르면 요청이 두 번 감 → 첫 번째가 지움 → 두 번째는 본인 글 확인(`getOwnBoard`)에서 삭제글이라 조회가 안 됨 → `NotFoundException` → 목록 + "게시글을 찾을 수 없습니다." — **실제로는 지워졌는데 실패처럼 보임**.

**바뀐 뒤**: 삭제 form의 `submit` 때 버튼을 `disabled`. 제출은 막지 않음(`preventDefault` 없음 — form 제출 그대로, 글쓰기처럼 fetch로 바꾸지 않음).

```
detail.html
  삭제 form (id 붙임) → submit 이벤트 → 버튼 disabled → 브라우저가 form 제출(그대로) → 서버 → redirect 목록
```

- 실패해도 다른 화면으로 redirect되므로 버튼을 다시 켤 필요가 없음(글쓰기는 같은 화면에 남아서 다시 켰음).
- 막는 층은 화면(버튼)만. 이미 시작된 두 요청이나 화면을 거치지 않은 요청까지 막으려면 서버 층이 필요하지만, 지금 증상(두 번째가 실패 안내)은 화면 층으로 충분.

## 3. 첨부 크기 미리 검사

**지금**: 제한을 넘는 파일 → 서버 413 → 브라우저가 응답을 못 받고 `(failed)` → `catch` "전송에 실패했습니다". 큰 파일이면 다 올라갈 때까지 기다린 뒤에야 실패.

**바뀐 뒤**: 글쓰기 JS가 보내기 **전에** 고른 파일 크기를 봄 → 제한보다 크면 alert "파일이 너무 큽니다." 후 보내지 않음.

```
submit → preventDefault → (새) 파일이 있고 크기 > 제한 → alert, 끝(버튼은 아직 안 껐으니 그대로)
                        → 아니면 지금처럼 FormData → 버튼 disabled → fetch
```

- 파일은 `form.file.files[0]`(파일 칸 `name="file"`), 크기는 `.size`(바이트).
- 서버 제한(`spring.servlet.multipart.max-file-size`)은 그대로 — 화면 검사는 편의, 막는 건 서버(확장자의 `accept`와 같은 관계). 413 갈래도 그대로 둠.

## 4. 확인 방법

| 해 볼 것 | 성공 기준 |
|---|---|
| 삭제 버튼 빠르게 두 번 | 목록으로 가고 "찾을 수 없습니다" 안내가 안 뜸, 글은 지워짐 |
| 삭제 한 번(평소) | 지금처럼 지워지고 목록 |
| 제한보다 큰 파일 저장 | 바로 alert "파일이 너무 큽니다.", Network에 저장 요청이 안 생김, 입력값 그대로 |
| 제한보다 작은 파일 | 지금처럼 저장 → 상세 |
