# 2026-11-04 작업 설계 — 글 저장 후 상세 화면으로 이동

## 1. 개요

| 항목 | 내용 |
|---|---|
| 목적 | 받은 의견(10/27, 글쓰기 fetch 설계 10장 5번): 저장 성공 후 어디로 갈지는 **정책 문제라 둘 다 해 보기** — 목록 이동은 10/27에 함, 이번엔 **상세 이동** |
| 범위 | 글쓰기 저장(`/api/board/save`) 성공 뒤 이동만. 수정 성공 뒤 이동은 그대로(이미 상세로 감) |
| 안 하는 것 | 글쓰기·수정 한 화면(따로 설계), 실패 갈래(그대로) |

## 2. 흐름

```
write.html (JS)
  fetch(form.action) → BoardRestController.saveBoard
    → BoardService.saveBoard: board INSERT → useGeneratedKeys가 boardVo.boardIdx를 채움 → (파일) → 새 글 번호 return
  ← 201 { message: null, data: 새 글 번호 }
  res.ok → body = await res.json() → alert('저장되었습니다.') → location.href = '/board/detail/' + body.data
```

## 3. 바뀌는 곳

| 파일 | 지금 | 바뀐 뒤 |
|---|---|---|
| `BoardService.saveBoard` | `void` | **`int`**(새 글 번호). `return`이 **두 곳** — 파일이 없을 때 중간에 끝나는 `return;`과 맨 끝 — 둘 다 `boardVo.getBoardIdx()` |
| `BoardRestController.saveBoard` | `ResponseDto<BoardWriteRequest>`, `data`에 받은 입력(`req`)을 그대로 돌려줌 | **`ResponseDto<Integer>`**, `data`에 새 글 번호. 입력을 되돌려 주는 건 화면이 이미 아는 값이라 쓸 데가 없었음 |
| `write.html` | `res.ok` → alert → `/board/list` | `res.ok` → 본문 읽기(`res.json()`) → alert → `/board/detail/` + 번호 |

- 새 글 번호는 따로 조회하지 않음: `insertBoard`의 `useGeneratedKeys="true" keyProperty="boardIdx"`가 INSERT 직후 같은 `boardVo`에 번호를 채워 둠(파일 저장도 이미 이 번호를 씀).

## 4. 확인 방법

| 해 볼 것 | 성공 기준 |
|---|---|
| 파일 없이 저장 | alert 뒤 방금 쓴 글의 상세(주소 번호 = DB 새 글 번호) |
| 파일 넣고 저장 | 상세에 첨부 파일이 보이고 내려받기 됨 |
| Network의 저장 응답 | 201, 본문 `data`에 번호 |
| 실패(빈 제목·지정 밖 파일) | 지금처럼 alert + 글쓰기 화면 그대로 |
