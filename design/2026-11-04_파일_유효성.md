# 2026-11-04 작업 설계 — 첨부 파일 유효성(받을 종류만 받기)

## 1. 개요

| 항목 | 내용 |
|---|---|
| 목적 | 받은 의견(10/27): **"받을 종류를 정하고, 확장자가 다르면 튕기기"**. 지금은 어떤 파일이든 저장됨(10/27 설계에서 "안 하는 것"으로 미뤄 둠) |
| 왜 | 받을 종류가 정해져 있어야 **종류별 처리**를 고를 수 있음(이미지는 화면에 띄움, 영상은 재생, 나머지는 내려받기). 서비스는 보통 정해진 종류만 받음. 보안은 우리 구조에선 부수적(5장) |
| 범위 | 글쓰기 첨부(파일이 들어오는 곳은 글 저장 하나 — 수정 화면엔 파일 칸 없음). 저장은 `BoardService.saveBoard` → `FileStore.store`를 지나므로 **`store` 한 곳**에서 막음(폼 저장 길 `/board/save`는 이번에 지움 — 10장 5번) |
| 안 하는 것 | 파일 내용 검사(확장자만 바꾼 파일은 못 잡음 — 5장), 크기 제한 변경(지금 설정 그대로, 413), 파일 이름 길이·특수문자 검사 |

## 2. 무엇을 잡나

| 들어온 파일 | 지금 | 바뀐 뒤 |
|---|---|---|
| 허용 목록에 있는 확장자(`a.pdf`) | 저장 | 저장(그대로) |
| 대문자 확장자(`A.PDF`, `b.Jpg`) | 저장 | **저장** — 소문자로 바꿔 비교 |
| 목록에 없는 확장자(`a.exe`, `a.html`) | 저장 | **400 + 문구**, 글도 파일도 남지 않음 |
| 확장자 없음(`README`) | 저장(확장자 없이) | **400** — 종류를 알 수 없음 |
| 점이 여럿(`a.jpg.exe`) | 저장 | 마지막 점 뒤(`exe`)로 판단 → **400** |
| 파일 없이 글만 | 저장 | 저장(그대로, 검사 안 함) |

- 방식은 **허용 목록**(받을 것만 적음). 막을 목록(`exe`만 막기)은 새 위험한 종류가 나올 때마다 빠짐(10/27 정리: 허용 목록 > 막을 목록).

## 3. 처리 흐름

```
write.html (JS, 지금 그대로)
  → BoardRestController.saveBoard
  → BoardService.saveBoard          @Transactional
      ① 제목 비었나            → BlankValueException(400)       (지금)
      ② board INSERT
      ③ 파일이 있으면 FileStore.store
           ③-1 확장자 뽑기 → 허용 목록에 없으면 InvalidValueException(400)   ← 추가
           ③-2 디스크 저장(지금)
         → board_file INSERT
  → 실패: ApiExceptionHandler → 400 { message: ErrorCode 문구 }
           @Transactional이 ②의 글 INSERT를 되돌림
  → write.html else 갈래: alert(body.message ?? …), 입력값·파일 유지, 버튼 다시 켬 (지금 코드로 이미 됨)
```

- **검사는 `store` 맨 앞**(10장 3번): 검사와 저장이 한 메서드에 있어 "저장되는 파일은 모두 검사를 지남"이 구조로 보장됨. 글 INSERT 뒤에 걸리지만 `@Transactional`이 되돌리고, 디스크에 쓰기 전이라 지울 파일도 없음.

## 4. 바뀌는 곳

| 파일 | 무엇을 |
|---|---|
| `ErrorCode` | **공통** 줄에 `FILE_TYPE_NOT_ALLOWED(HttpStatus.BAD_REQUEST, "지정된 파일만 올릴 수 있습니다.")` — 던지는 곳이 공통 `FileStore`라 게시판 이름(`BOARD_`)을 안 붙임 |
| 예외 | 기존 `InvalidValueException` 재사용(10장 2번) |
| `FileStore` | 허용 목록 상수 `Set.of("jpg", …)`(소문자, 점 없이) + `store` 맨 앞 검사: 지금 뽑는 `ext`(점 포함, 없으면 `""`)에서 점을 떼고 `toLowerCase()` → `contains`가 아니면 던짐. 확장자 없음(`""`)도 목록에 없어 걸림. 지금은 파일을 받는 기능이 게시판 하나라 목록도 여기 하나(두 번째 기능이 생기면 기능별 목록을 넘겨받는 꼴로 — TODO "공용 파일 확장") |
| `BoardService` | 바뀌는 것 없음 |
| `BoardController.saveBoard`(폼 길 `/board/save`) | **지움**(10장 5번) — 안 쓰는 길 |
| `write.html` | 폼 `th:action="@{/api/board/save}"`로 바꾸고 JS는 `fetch(form.action, …)` — `th:action`은 CSRF 숨은 칸(`FormData`가 담아 감) 때문에 꼭 있어야 함, 주소를 한곳에만 적고 앱 위치(context path)도 붙음. 파일 칸에 `accept=".jpg,.jpeg,.png,…"` + 아래 `form-text` 안내("jpg, jpeg, png, gif, pdf, txt, hwp, docx, xlsx, pptx 파일만 올릴 수 있습니다."). `accept`는 고르는 창에서 목록만 보여 주는 **편의** — "모든 파일"로 바꾸면 무시되므로 막는 건 서버 |

## 5. 한계와 보안(알고 넘어감)

- 확장자 제한이 보안 장치가 되는 건 **올린 파일을 서버가 그대로 열어 주는 구조**일 때(예: `.html`을 올려 그 주소로 열면 남의 브라우저에서 스크립트가 돎). 우리는 업로드 폴더가 `static/` 밖이고 `attachment`로만 돌려줘서 이 위험이 원래 작음 → 이번 검사의 주목적은 종류 정하기.
- 확장자는 **이름일 뿐**이라 `virus.exe`를 `virus.jpg`로 바꾸면 통과. 진짜 내용 검사(파일 앞 몇 바이트의 형식 표시 확인 등)는 이번엔 안 함.
- 지금은 받은 파일을 **내려받기(`attachment`)로만** 돌려주고 화면에 열지 않아서 위험이 작음. 나중에 이미지 미리보기(TODO, `inline`)를 하면 그때 내용 검사가 필요해짐.

## 6. 확인 방법

| 해 볼 것 | 성공 기준 |
|---|---|
| 허용 파일(`pdf`, `jpg`) 첨부해 저장 | 지금처럼 저장, 상세에서 내려받기 됨 |
| 대문자 확장자(`.PNG`) | 저장됨 |
| `.exe`(또는 `.html`) — 파일 창에서 "모든 파일"로 바꿔 고름 | alert에 새 문구, 글쓰기 화면·입력값 그대로 |
| 위 실패 뒤 DB·업로드 폴더 | 글·파일 줄 늘지 않음, 폴더에 새 파일 없음 |
| 확장자 없는 파일 | 400 문구 |
| 파일 없이 글만 | 저장됨 |
| (길 정리 뒤) 저장 요청을 개발자 도구 Network에서 | 주소 `/api/board/save`, 403 없이 저장(CSRF 숨은 칸이 그대로 감) |

## 10. 결정·검토 반영

| # | 무엇을 | 결정 | 이유 |
|---|---|---|---|
| 1 | 허용 목록(11/04) | 이미지 `jpg`·`jpeg`·`png`·`gif` + 문서 `pdf`·`txt`·`hwp`·`docx`·`xlsx`·`pptx`. **영상·`zip`은 뺌** | 처리 방법별로 묶음(이미지 = 나중에 화면에 띄울 수 있음, 문서 = 내려받기). 영상은 재생 계획이 없고, `zip`은 안을 볼 수 없음 |
| 2 | 예외(11/04) | 기존 **`InvalidValueException`** 재사용("값은 있는데 규칙에 안 맞을 때") | 역할이 나뉘어 있음: `ErrorCode` = 상태 코드 + 회원 문구, **자식 예외 = catch에서 종류를 가르는 용도**(화면 컨트롤러의 `instanceof`·`catch`). 확장자 위반은 비밀번호 규칙 위반과 같은 종류라 새 클래스가 필요 없음 |
| 3 | 검사 위치(11/04) | **`FileStore.store` 맨 앞**(목록도 `FileStore`, `ErrorCode`는 공통 이름) | 검사와 저장이 한 메서드에 있어 검사를 빠뜨린 저장이 생길 수 없음. INSERT 뒤에 걸리지만 `@Transactional`이 되돌리고 디스크엔 쓰기 전. 대안(Service 맨 앞에서 따로 부르기)은 INSERT를 아끼지만 부르는 쪽이 잊을 수 있음 |
| 4 | 문구·안내(11/04) | 서버 문구는 **"지정된 파일만 올릴 수 있습니다."**, 허용 종류는 **글쓰기 화면 파일 칸 아래 안내**(`form-text`) + `accept` | 문구에 목록을 넣으면 목록을 바꿀 때 문구도 고쳐야 함. 고르기 전에 보이는 화면 안내가 회원에게 더 쓸모 있음. 목록이 서버 상수·화면 안내·`accept` 세 곳에 적히는 건 감수(바꿀 일이 드묾) |
| 5 | 폼 저장 길 `/board/save`(11/04) | **지움**. 폼은 `th:action="@{/api/board/save}"` + JS `fetch(form.action, …)` | 10/27 fetch로 옮긴 뒤 "JS가 안 돌 때" 예비 길로 남겼음(받은 의견: 안 쓰는 길은 지우는 게 원칙, 학습 중이라 남겨도 됨). 새 규칙마다 두 곳을 고쳐야 해서, 안 쓰는 곳을 유지보수할 바엔 지금 정리. `th:action`은 빼면 CSRF 숨은 칸이 사라져 fetch도 403이라 주소만 API로. 지우면 코드에서 사라지는 학습 모양은 **실패 → `Model` + 같은 화면 `return`**(다른 곳은 전부 flash + redirect) 하나, 개념은 기록지 10/16~10/21에 있음. 예전 코드: `git show b9da584:board/src/main/java/com/study/skillup/board/controller/BoardController.java` |
