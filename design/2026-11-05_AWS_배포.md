# 2026-11-05 작업 설계 — AWS(EC2)에 게시판 배포

## 1. 개요

| 항목 | 내용 |
|---|---|
| 목적 | 받은 의견(11/04 저녁): "AWS 배포 편하게 해 봐라". 내 PC에서만 돌던 게시판을 클라우드 서버 한 대에 올려 브라우저로 접속 |
| 범위 | EC2 한 대에 jar 하나 + DB 하나. 빌드 → 옮기기 → 실행 → 서비스 등록 → 정리까지 |
| 안 하는 것 | 도메인·HTTPS, nginx, Docker, 자동 배포(CI/CD), RDS(관리형 DB), 여러 대 |

## 2. 그림

```
[내 PC]                                  [AWS 서울 리전]
 mvnw package → skillup-….jar  ──scp──→     EC2(리눅스 1대)
 키 파일(.pem, 저장소 밖)    ──ssh──→       ├ Java 21
                                           ├ skillup.jar + 옆에 서버용 application.properties
                                           ├ DB 파일(9장 1번)
                                           └ 업로드 폴더
 브라우저 ── http://<서버 주소>:8080 ──→   보안 그룹(들어올 수 있는 IP·포트를 정하는 방화벽)
```

## 3. 단계

| # | 무엇 | 어디서 | 확인 |
|---|---|---|---|
| 0 | `mvnw package`로 jar 만들기 → `java -jar`로 실행 | 내 PC | IntelliJ 없이 `localhost:8080`이 열림 |
| 1 | 예산 알림(Budgets) | AWS 콘솔 | 알림 메일 주소 등록됨 |
| 2 | EC2 만들기: 서울 리전, 무료 범위 작은 사양, OS(9장 2번), 키 페어 새로 만들어 `.pem` 내려받기, 보안 그룹 | AWS 콘솔 | 인스턴스 "실행 중" |
| 3 | SSH 접속 → Java 21 설치 | 내 PC 터미널 → 서버 | `java -version` = 21 |
| 4 | jar 올리기(scp) + 서버용 설정 파일 만들기 + DB 준비 | 내 PC → 서버 | 파일이 서버에 있음 |
| 5 | `java -jar` 실행 → 내 브라우저로 접속 → 가입·로그인·글쓰기·파일 → 서비스 등록(systemd, 재부팅에도 자동 시작) | 서버 | 화면·기능 동작, 서버 재부팅 뒤에도 접속 |
| 6 | 끝나면 정리: 계속 둘지(요금) / 중지 / 종료(디스크·IP까지) | AWS 콘솔 | 9장 4번 |

## 4. 설정을 내 PC와 서버로 나누는 방법

- 지금 `application.properties`(jar 안)에는 내 PC용 값(H2 서버 모드 주소, 윈도우 업로드 경로)이 들어 있음.
- 스프링 부트는 **jar와 같은 폴더의 `application.properties`를 jar 안 것보다 먼저** 읽음 → 서버에는 **바뀌는 키만** 적은 파일을 jar 옆에 둠(DB 주소·계정, 업로드 경로). 이 파일은 서버에만 있고 저장소에 올리지 않음.
- 코드·jar는 그대로, 값만 장소별로 다름.

## 5. 빌드 때 주의

- `mvnw package`는 시험(`src/test`)도 돌림. `SkillUpApplicationTests`·`MemberJoinApiTest`는 H2 서버가 켜져 있어야 통과 → **H2를 켜고 빌드**(시험이 도는 게 정상 확인도 됨). 시험을 건너뛰는 `-DskipTests`는 알고만 둠.
- 결과물: `skillup/target/skillup-0.0.1-SNAPSHOT.jar`(이름은 빌드 뒤 확인).

## 6. 보안 — 지키는 것

- 키 파일(`.pem`)은 **실습 저장소 폴더 밖**에. 윈도우에선 내 계정만 읽게 권한을 좁혀야 ssh가 받아 줌(안내 때 명령 제공).
- 키 파일 내용·서버 IP·AWS 계정 값·DB 비밀번호는 대화·설계·작업 로그·저장소에 적지 않음(명령은 `<서버 주소>`·`<키 파일 경로>` 자리로 안내).
- 보안 그룹: SSH(22)는 **내 IP만**. 앱 포트는 9장 3번.
- 서버의 DB 계정·비밀번호는 내 PC와 다르게.

## 7. 확인 방법

| 해 볼 것 | 성공 기준 |
|---|---|
| 내 PC에서 `java -jar` | IntelliJ 없이 화면·로그인 동작 |
| 서버 주소:8080 접속 | 메인 화면 |
| 가입 → 로그인 → 글쓰기(파일 포함) → 상세 → 내려받기 → 수정·삭제 | 내 PC와 같게 동작, 업로드 파일이 서버 폴더에 |
| 서버 재부팅(`sudo reboot`) 뒤 다시 접속 | 서비스가 자동으로 떠 있음 |
| 허용 안 한 IP(예: 휴대폰 데이터)로 접속 | 안 열림(3번에서 내 IP만 고른 경우) |

## 9. 정할 것

1. **DB** — (가) **H2 파일 모드**: 서버 안에서 앱이 직접 파일로 씀(별도 DB 프로그램 없음, 주소만 `jdbc:h2:file:…`), 테이블은 내 PC H2에서 만들기 문(DDL)을 뽑아 서버에서 한 번 실행 / (나) **MariaDB 설치**: 회사와 같은 DB, 설치·계정·드라이버 의존성 추가·DDL 문법 확인이 더 듦. 안: **(가)로 오늘 끝내기**, MariaDB는 다음에 따로
2. **OS** — (가) Amazon Linux 2023(AWS 기본, Java는 Amazon Corretto 21을 `dnf`로) / (나) Ubuntu 24.04(자료 많음, `apt`). 안: (가) — EC2 기본값이라 설정할 게 적음
3. **앱 포트(8080) 공개 범위** — (가) **내 IP만** / (나) 누구나. 안: (가) — 테스트 계정·H2·HTTPS 없음. 회사 IP가 바뀌면 보안 그룹만 고치면 됨
4. **끝나고** — (가) 중지(디스크 요금만, 다시 켜면 IP가 바뀜) / (나) 종료(전부 삭제, 요금 없음) / (다) 무료 범위 안에서 당분간 켜 둠. 안: 마무리 확인 뒤 정함(보고 때 보여 줄지에 따라)

## 10. 결정·검토 반영

| # | 무엇을 | 결정 | 이유 |
|---|---|---|---|
| 1 | DB(11/05) | **H2 파일 모드로 먼저 배포 → 이어서 MariaDB(같은 EC2)로 교체** | 배포 뼈대를 먼저 확실히(막히면 원인이 배포 쪽뿐), 교체는 "드라이버·설정만 바꾸면 DB가 바뀜"을 따로 연습. 둘 다 SQL + JDBC라 매퍼 SQL은 그대로일 가능성이 높고 테이블 만드는 문(DDL)만 MariaDB 문법으로. 새 주제는 받은 의견상 자유롭게 해도 됨(본인 판단) |
| 2 | OS(11/05) | Amazon Linux 2023 | 안대로(EC2 기본값) |
| 3 | 앱 포트 공개 범위(11/05) | 내 IP만 | 안대로(테스트 계정·H2·HTTPS 없음) |
| 4 | 프로젝트 이름(11/05) | 폴더 `board/` → `skillup/`, `pom.xml` `artifactId`·`name`·`description`, `spring.application.name` → `skillup` | 10/28엔 자바 패키지(`com.study.skillup`)만 바꿈. 저장소 맨 위 폴더·jar 이름·로그 이름이 `board`라 게시판 기능과 헷갈림(10/27 의견 때 실제로 헷갈림). jar 이름이 서버 파일·서비스 등록에 들어가니 배포 전에 |
| 5 | 테이블 만들기(11/05) | 내 PC H2에서 `SCRIPT NODATA NOPASSWORDS … TABLE …`로 뽑아 **`skillup/db/schema-h2.sql`**로 정리(계정 줄·내 PC 번호(`RESTART WITH`)·행 수 메모 삭제, `CREATE TABLE IF NOT EXISTS` + 제약을 표 안에 이름 붙여), 서버 설정 `spring.sql.init.mode=always` + `schema-locations=file:…`로 켤 때마다 실행 | 사람이 콘솔에서 한 번 하던 걸 스프링이 켤 때마다 하게 되어 여러 번 실행해도 안전해야 함. 테이블 정의가 처음으로 파일로 남음(MariaDB 교체의 출발점, 버전별로 쌓는 도구는 Flyway·Liquibase) |
| 6 | 서버로 보내는 것(11/05) | **`scp`로 jar(+ SQL 파일)만** — 서버에서 `git clone` 후 빌드는 안 함 | 빌드는 한 곳에서 한 번(시험 통과), 서버는 결과물만 실행. clone이면 서버에 개발 도구·저장소 인증·빌드 자원이 필요하고 H2 서버가 없어 시험도 실패 |
| 7 | 끝난 뒤(11/05) | **켜 둠**(무료 플랜 크레딧, 12/16까지) | 작은 인스턴스 하나라 크레딧을 다 쓸 일이 없음, 보고 때 실제 주소로 보여 줄 수 있음. 다 쓰면 종료(디스크·IP까지) |
| 8 | MariaDB 교체(11/05) | **뒤로**(금요일 보고 뒤 또는 다음 주) | 본인: "개인적인 욕심, jQuery는 받은 의견" → 의견부터 |
