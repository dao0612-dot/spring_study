# 2026-11-05 작업 설계 — 상세 화면 시각 표시(수정 시각이 있으면 그것만)

## 1. 개요

| 항목 | 내용 |
|---|---|
| 목적 | 상세 화면에 지금 작성 시각과 수정 시각이 **둘 다** 나옴(수정 시각은 `th:if`로 있을 때만). 수정된 글은 **수정 시각만**, 아닌 글은 작성 시각만 보이게(`detail.html` 16번 줄 `TODO` 주석) |
| 대상 | `templates/board/detail.html` 한 파일(15~17번 줄) |
| 안 하는 것 | 서버 코드·SQL(이미 `upt_dttm`을 조회 중, 수정할 때 `current_timestamp`로 채움), 목록 화면 |

## 2. 지금

```html
<p … th:text="${#temporals.format(board.regDttm, 'yyyy-MM-dd HH:mm')}"></p>
<!--TODO: 수정일이 존재할 시 작성일이 안보이도록-->
<p … th:if="${board.uptDttm}" th:text="${#temporals.format(board.uptDttm, 'yyyy-MM-dd HH:mm')}"></p>
```

- 숫자만 있어서 어느 쪽이 작성이고 어느 쪽이 수정인지 화면에서 구분이 안 됨.

## 3. 방법(둘 중 하나)

| | (가) `th:if` / `th:unless` 짝 | (나) 삼항 한 줄 |
|---|---|---|
| 꼴 | 작성 줄에 `th:unless="${board.uptDttm}"`, 수정 줄은 지금 그대로 `th:if` | `<p>` 하나에 `th:text="${board.uptDttm != null} ? '수정 ' + … : '작성 ' + …"` |
| 장점 | 지금 코드에 한 속성만 더함, 줄마다 하는 일이 분명 | 줄이 하나라 "둘 중 하나만"이 꼴로 드러남 |
| 단점 | 조건을 두 군데에 씀 | 줄이 길어짐(형식 지정이 두 번) |
| 이어지는 것 | `th:unless` = `th:if`의 반대(조건이 참이면 태그를 지움) | 11/04 `form.html`의 `${board == null} ? :`와 같은 꼴 |

- 어느 쪽이든 앞에 **"작성"/"수정" 글자**를 붙여 구분(예: `수정 2026-11-05 14:30`).

## 4. 확인 방법

| 해 볼 것 | 성공 기준 |
|---|---|
| 새 글 쓰고 상세 | `작성 …`만 보임 |
| 그 글 수정 후 상세 | `수정 …`만 보임, 시각이 수정한 때 |
| 끝나면 jar 다시 빌드 → 서버 갱신(멈춤 → jar 바꿈 → 켬) | 서버에서도 같게 |

## 9. 정할 것

1. **방법** — (가) `th:if`/`th:unless` / (나) 삼항. 안: **(가)** — 바꾸는 양이 가장 적고 `th:unless`라는 새 속성 하나를 익힘(삼항은 어제 해 봄)
2. **글자** — 시각 앞에 "작성"/"수정"을 붙일지. 안: 붙임

## 10. 결정·검토 반영

| # | 무엇을 | 결정 | 이유 |
|---|---|---|---|
| 1 | 방법(11/05) | **(가) `th:if` / `th:unless` 짝** | 지금 코드에 속성 하나만 더함. 삼항과의 차이: `th:if`/`th:unless`는 **태그를** 고르고(두 경우 모양이 다를 때 편함), 삼항은 **글자를** 고름(모양이 같고 글자만 다를 때) |
| 2 | 글자(11/05) | 앞에 `작성일: ` / `수정일: `, `+`로 이어 붙임. 두 줄 class 같게(`mb-1`) | 한 줄만 보이니 숫자만으론 구분 안 됨. `th:text`는 태그 안을 통째로 바꾸므로 고정 글자도 식 안에(다른 꼴: `\|…${}…\|`, 바뀌는 부분만 `<span>`) |
