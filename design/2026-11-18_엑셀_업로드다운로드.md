# 2026-11-18 작업 설계 — 엑셀 다운로드·업로드 (1) 직접 구현

## 1. 개요

| 항목 | 내용 |
|---|---|
| 목적 | 받은 의견(11/17): 엑셀 업로드·다운로드를 **두 갈래**로 만들고 장단점 비교 — (1) 회사 코드를 보지 않고 직접(POI) → (2) 회사 유틸을 붙여 넣어 씀. 이 문서는 **(1)** |
| 대상 | 다운로드 = 게시판 목록 → `.xlsx` / 업로드 = `.xlsx` → 게시글 여러 개 |
| 안 하는 것 | 파일 비밀번호 암호화(비교표에 "회사 유틸은 있음"으로만), 검색 조건, 작성자 이름(JOIN 새 SQL — 필요하면 나중에) |
| 진행 | 받은 의견을 준 쪽 검토 없이 본인과 같이 구상하고 바로 구현(11/18 본인 결정 — 특정 기술 지시가 없었음). 하면서 떠오른 것은 10장에 반영 |

## 2. 들여오기

- `pom.xml`에 `org.apache.poi:poi-ooxml` **5.4.1**(`.xlsx` = XSSF). 버전은 본인이 Maven Central에서 확인해 적음.

## 3. 다운로드

| 항목 | 내용 |
|---|---|
| 주소 | `GET /board/excel/download` — 화면 목록 위 링크 `<a href="/board/excel/download">`. 받기만 하므로 JS·CSRF 없음 |
| 로그인 | 목록과 같게 공개 → `SecurityConfig` 공개 주소에 추가 |
| 데이터 | 기존 `BoardService.getBoardList()` 그대로(삭제 안 된 글, 최신순) — 새 SQL 없음 |
| 칸 | 번호(`boardIdx`)·제목·내용·작성자 번호(`memberIdx`)·작성일(`regDttm`) |
| 흐름 | 목록 조회 → 통합문서·시트 → 1행 머리 → 2행부터 글 하나 = 한 줄 → 응답 머리(파일 종류·파일 이름) → `response`에 쓰기 |
| 비교 거리 | 회사는 POST + JSON + blob(사유·비번을 같이 보내야 해서) ↔ 우리는 보낼 것이 없어 GET 링크 |

## 4. 업로드

| 항목 | 내용 |
|---|---|
| 주소 | `POST /api/board/excel/upload` — 로그인 필요(기본 규칙), fetch + `FormData` + CSRF 헤더(글쓰기와 같은 방식) |
| 양식 | 1행 = 머리(제목·내용), 2행부터 한 줄 = 글 하나. 완전히 빈 줄은 건너뜀 |
| 작성자 | 로그인 회원(`@AuthenticationPrincipal LoginMember`) |
| 검사 | 업로드 서비스: `.xlsx`만, 글 줄 수 1~100, 빈 줄 건너뜀. 제목 빈칸은 `saveBoard`가 검사(글쓰기와 같은 규칙, 10장 8번) |
| 저장 | 줄마다 기존 **`boardService.saveBoard(new BoardWriteRequest(제목, 내용), null, memberIdx)`** — 파일 `null`이면 첨부 없이 끝(69~71줄). 업로드 메서드 `@Transactional` 안 → 한 줄이라도 예외면 **앞 줄까지 전부 롤백** |
| 응답 | `ResponseDto<Integer>` = 저장한 글 수 → 화면 alert 뒤 목록 새로고침 |
| 화면 | 목록 화면에 파일 칸 + "엑셀 올리기" 버튼(로그인했을 때만 보일지는 구현 때 정함) |

## 5. 구조·파일

| 파일 | 할 일 |
|---|---|
| `pom.xml` | POI 추가 |

| `board/service/BoardExcelService.java`(새) | 엑셀 만들기 / 읽기·검사 / 저장 |

| `config/SecurityConfig.java` | 다운로드 주소 공개 |
| `templates/board/list.html` | 다운로드 링크, 업로드 칸·버튼·JS |
| (2) 갈래 | `com.study.skillup.tabtap` 패키지 — **파일을 만들기 전에** 저장소 루트 `.gitignore`에 등록 후 `git check-ignore`로 확인 |

## 6. 확인 방법

| 해 볼 것 | 성공 기준 |
|---|---|
| 목록에서 다운로드 링크 | `.xlsx`가 받아지고 엑셀에서 열림, 줄 수 = 목록 글 수, 한글 파일 이름 |
| A열 제목·B열 내용으로 만든 파일 올리기 | 그 수만큼 글이 늘어남(받은 파일은 A열이 번호라 그대로는 안 맞음 — 10장 9번) |
| 제목 빈 줄이 섞인 파일 | 400 + 안내, **글이 하나도 안 늘어남** |
| `.xls`·`.txt` 파일 / 101줄 파일 / 빈 파일 | 400 + 안내 |
| 이름만 `.xlsx`로 바꾼 가짜 파일 | 400 + 형식 안내(POI가 던지는 예외 종류를 보고 처리 — `IOException`이 아니면 공통 500으로 갈 수 있음) |
| 로그아웃 상태로 업로드 | 막힘(403 등) |
| 제목 칸에 숫자만 | 글자로 저장됨(셀 종류가 숫자여도) |

## 10. 결정·검토 반영

| # | 무엇을 | 결정 | 이유 |
|---|---|---|---|
| 1 | 진행(11/18) | 받은 의견을 준 쪽 검토 없이 같이 구상 → 바로 구현 | 본인: 특정 기술 지시가 없었음 |
| 2 | 다운로드 방식(11/18) | GET 링크 | 보낼 것이 없음. 회사 방식(POST + blob)과의 차이는 비교 거리 |
| 3 | 칸(11/18) | 번호·제목·내용·작성자 번호·작성일 | 처음엔 "작성자"였으나 목록 SQL에 이름이 없음(`member_idx`뿐) → 기존 SQL 그대로 쓰려고 번호로 |
| 4 | 잘못된 줄(11/18) | 전부 거절, 검사 먼저 → 저장은 그다음 | 절반만 들어가면 어디까지인지 찾기 어려움. 검사를 앞에 두면 롤백할 일 자체가 줄고, `@Transactional`은 DB 실패 대비 |
| 5 | 코드 위치(11/18) | `board` 안 엑셀 전용 컨트롤러·서비스 | 기존 파일에 섞지 않아야 (2) 갈래와 비교 경계가 깔끔 |
| 7 | 형식 오류 코드(11/18, 구현 중) | 새로 안 만들고 기존 **`FILE_TYPE_NOT_ALLOWED`** 재사용. 검사 자체는 업로드 서비스에서 `.xlsx`만(`FileStore` 허용 목록엔 pdf 등도 있어 그대로 못 씀). 무엇이 "지정된 파일"인지는 화면(`accept=".xlsx"`·안내)이 알려 줌. 제목 빈칸도 기존 **`BOARD_TITLE_BLANK`** 재사용(몇 번째 줄인지는 개발자 메시지·로그에). **새 코드는 줄 수 하나** | 본인: 뜻이 같은 코드를 둘 두지 않음. `ErrorCode` 문구 = 회원이 무엇을 고칠지 알려 주는 것 |
| 8 | 글쓰기(첨부)와의 관계(11/18, 구현 중) | **화면·API는 따로**(목록 화면 + `/api/board/excel/upload`), **글 하나 저장은 기존 `saveBoard` 재사용**. 4번의 "검사 먼저 → 저장"은 "형식·줄 수 먼저 → 저장하며 제목 검사(걸리면 롤백)"로 바뀜 | 본인 질문("글쓰기와 파일 업로드는 한 기능이었는데 따라갈지 확실히"). 글쓰기의 파일 = **첨부**(디스크 보관 + `board_file`, 글 하나에 붙음) ↔ 엑셀 = **재료**(읽어서 글 여러 개, 보관 안 함). `.xlsx`는 이미 첨부 허용 목록에 있어 같은 API면 둘을 구분 못 함. 대신 글 규칙(제목·INSERT 확인)은 한곳에 두려고 저장 길은 그대로 씀 |
| 9 | 업로드 칸 위치(11/18, 구현 중) | **고정 열: A = 제목, B = 내용** | 다운로드 파일은 A열이 번호라 그대로 다시 올리면 번호가 제목이 됨 → 머리 글자로 열을 찾는 안(받은 파일 재업로드 가능)은 코드가 늘어 비교 뒤 더할 거리로 |
| 6 | 컨트롤러 종류·응답(11/18, 구현 중) | `BoardExcelController` 하나를 **`@RestController`**로, 다운로드는 **`ResponseEntity<byte[]>`**(서비스가 `byte[]`를 만듦) | `ApiExceptionHandler`가 `@RestController`에만 붙음 → 업로드 JSON 오류 응답에 필요. 다운로드는 기존 첨부 내려받기(`ResponseEntity` + `ContentDisposition`)와 같은 꼴. 회사는 `void` + `response`에 직접 씀 → 비교 거리 |

| 10 | 가짜 `.xlsx` 처리(11/18, 시험 중) | `catch (NotOfficeXmlFileException \| IOException e)` → `InvalidValueException(FILE_TYPE_NOT_ALLOWED)`(400) | 시험 ⑤에서 500 "예상치 못한 오류" → 로그 맨 위 `NotOfficeXmlFileException`(POI가 `ZipException`을 감싼 실행 시간 예외라 `IOException` catch를 지나침). 깨진 진짜 `.xlsx`의 `IOException`도 회원이 고칠 문제라 같이 400(공통 처리기의 "파일 **저장** 실패" 문구도 피함) |
| 11 | 로그인 안 한 업로드(11/18 정함 → 11/19 바꿈) | **업로드 form을 로그인했을 때만**: `BoardController.boardList`가 `@AuthenticationPrincipal`로 `loggedIn`을 Model에 → `<form th:if="${loggedIn}">`(버튼만이 아니라 form 통째 — 파일 칸·버튼은 한 묶음), JS는 `if (excelUpload)`로 감쌈(form이 없으면 등록 호출 자체가 `null` 오류). 안전망으로 생각한 `res.redirected` 분기는 **넣지 않음**(11/19 시험: 다른 탭 로그아웃 → 세션과 함께 CSRF 토큰도 사라져 **403이 먼저** → 기존 403 분기 "화면이 만료되었습니다". 302는 "토큰은 맞고 로그인은 안 됨"일 때만인데 form을 숨겨 그 길이 거의 없음 → 302가 다시 보이면 그때 넣음) | 11/19: 처음엔 숨기려면 새 의존성(`sec:authorize`)이 필요하다고 봤으나, 탭탭 `isExcel`처럼 Model + `th:if`면 의존성 없이 됨(본인 질문 "hidden/show 같은 방식은 구식인가"에서). `th:if` = HTML에 아예 없음(권한), JS `show`/`hide` = 있지만 안 보임(열고 닫기) | 공개 화면(목록)에 로그인 필요 버튼이 처음 생김. 시큐리티(디스패처 서블릿 밖)가 302 → fetch가 몰래 따라가 로그인 화면 HTML 200 → `res.json()` 문법 오류 → 공용 "전송 실패". `401` 분기는 폼 로그인에선 안 걸림. 서버 규칙(업로드 주소는 `permitAll`에 넣지 않음)은 그대로 — 화면은 편의 |
